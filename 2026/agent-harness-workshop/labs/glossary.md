# 📖 Glossary

The words this workshop uses, in one line each. The lab in brackets is where you meet the idea in practice.

- **Agent**: a model in a loop that can call tools to act (read files, run commands, edit code), not only answer. (Lab 00)
- **Harness**: everything around the model that turns it into an agent you can trust: the runtime, instructions, skills, roles, connections, guardrails and automation. (Lab 00)
- **Agent loop**: prompt, model reply, tool call, tool result, and again, until the model answers or a limit stops it. (Lab 00)
- **Context window**: everything the model sees in one turn: the system prompt, instructions, tool schemas, the conversation and the tool results. It is sent again, in full, every turn. (Lab 00)
- **Token**: the unit a model reads and writes, roughly four characters of English. Everything in the context costs tokens on every turn. (Lab 00)
- **Tool call**: JSON the model writes to ask the harness to run a tool; the harness decides whether it runs. (Lab 00)
- **AI credits**: what Copilot charges for model calls. `/usage` shows your spending, and `--max-ai-credits` caps a scripted run. (Lab 00)
- **Custom instructions**: Markdown files such as `AGENTS.md` that Copilot adds to the context of every conversation in a project. (Lab 01)
- **Canary**: a harmless rule (like a fixed last line) that proves an instruction file is really loaded. (Lab 01)
- **applyTo**: the glob in a scoped instruction file's frontmatter that says which files its rules are for. (Lab 01)
- **Skill**: a folder with a `SKILL.md` (and optional scripts and templates) that teaches the agent one job, loaded only when needed. (Lab 02)
- **Progressive disclosure**: keeping only names and descriptions in the context, and loading the full instructions when the model picks them. (Lab 02)
- **Custom agent**: a specialist defined in an `.agent.md` file, with its own instructions and an explicit list of tools. (Lab 03)
- **Least privilege**: giving each agent or script only the tools and permissions its job needs, so it can't do more even when asked. (Lab 03)
- **Subagent**: an agent the main agent delegates a task to; it works in its own, fresh context window. (Lab 03)
- **MCP server**: a program that offers tools (and data) to agents over the Model Context Protocol. (Lab 04)
- **Tool schema**: a tool's name, description and input format; the model only sees, and can only call, the tools whose schemas are in its context. (Lab 04)
- **Prompt injection**: text written by someone else (in a file, an issue or a tool result) that tries to make the model follow it instead of you. (Lab 04)
- **Hook**: your own program that the harness runs before or after a tool call; a `preToolUse` hook can block the call. (Lab 05)
- **Fail closed**: when a guard can't decide (it crashes or can't read the input), it blocks rather than allows. (Lab 05)
- **Plugin**: an installable bundle of agents, skills, hooks and MCP servers for Copilot CLI. (Lab 06)
- **APM**: the Agent Package Manager: an `apm.yml` manifest and an `apm.lock.yaml` lockfile that install a shared harness, pinned to versions. (Lab 06)
- **Extension**: your own JavaScript inside Copilot CLI, such as a slash command that answers without calling the model. (Lab 06)
- **Agentic workflow**: an agent that runs in GitHub Actions on an event, written in Markdown and compiled with `gh aw`. (Lab 07)
- **Safe outputs**: in an agentic workflow, the actions the agent may only propose (a label, a comment), applied by a separate job within your limits. (Lab 07)
- **Maturity level**: how far a harness has come, from L0 (bare runtime) to L5 (governed: pinned, shared, gated and owned). Each lab guide names the level it teaches. (Lab 00)
