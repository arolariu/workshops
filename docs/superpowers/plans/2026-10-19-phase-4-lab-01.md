# Phase 4 · Lab 01: Instructions, five tiers

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lab 01's homework ladder per spec §5.4: grow 🟡 medium "Rules for one folder" (30–45 min) and 🔴 hard "Prove it with data" (1–1.5 h), add 🟣 hard+ "The context diet" (1.5–2 h) and 💎 hard++ "Instructions as code" (2–3 h), each in the ticket format; fix the flaky hard agent check (the "without" run read `AGENTS.md` as a file).

**Architecture:** Each tier starts from the reference result of the tier before it (`src/` = predecessor `sol/` + this level's starter files). One small toolbox grows along the row, all in `scripts/` (a harness path, so `bring` carries it forward): `which-instructions.mjs` (medium: which instruction files apply to a path) → `ab.mjs` (hard: the A/B and ablation runner) → `lint-instructions.mjs` (hard+: vague rules, duplicates, contradictions, wrong commands, ≈tokens per path; it imports `which-instructions.mjs`) → `check-instructions.mjs` and `canaries.mjs` (hard++: the CI gate on top of the linter, and the canary regression suite). Checks import the learner's modules with `t.import`, run their CLIs in temp copies with `t.node`, and compare against small committed fixtures.

**Tech Stack:** Node 22+ ESM, `node:test`, the check kit (`labs/_harness/kit.mjs`), no npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-agent-harness-workshop-experience-design.md` §5.1, §5.2, §5.3, §5.4 (Lab 01 row, threads 📏 Measurement and 🪙 Tokens and budget), §5.10; overview plan `docs/superpowers/plans/2026-10-19-phase-4-ladders.md`; the exemplar `docs/superpowers/plans/2026-10-19-phase-4-lab-05.md`.

## Instruction facts this lab relies on (Copilot CLI 1.0.101-0, free commands and docs, 20 Oct 2026)

- **Discovery** ([docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions)): `AGENTS.md` and `.github/copilot-instructions.md` are read from the repository root, the working directory, the directories between them, "and any directories nested in the path of a file it is working on"; `.github/instructions/**/*.instructions.md` from the standard locations "but not intermediate directories".
- **No precedence** (same page): Copilot "combines their instructions … but does not define a general precedence order between these files. Avoid conflicting instructions." A conflict is resolved by editing, not by ordering.
- **What `copilot instruction list --json` shows** (spike in a throwaway folder inside the lab, deleted afterwards): from a folder with `AGENTS.md`, `.github/copilot-instructions.md`, `.github/instructions/d.instructions.md` and `packages/cli/AGENTS.md`, it lists the first three (with `applyTo` for the scoped file) and **not** the nested `packages/cli/AGENTS.md`. From `packages/cli` it lists `packages/cli/AGENTS.md` (`location: "working-directory"`) and the parent's `AGENTS.md` and `copilot-instructions.md` (`location: "repository"`, id `inherited-…`), but not the parent's `.github/instructions/`. Outside a git repository it still lists the folder's `AGENTS.md`.
- **Paths:** `sourcePath` uses backslashes on Windows (G7: normalise `\` to `/`), and is relative to the git root for `AGENTS.md` but to the working directory for `.instructions.md` files.
- **Path permissions** (`copilot help permissions`): "file access is restricted to paths within the current working directory and its subdirectories, plus the system temporary directory." A run in a copy can't read the original folder.
- **Trust** (`copilot help environment`, `COPILOT_ALLOW_ALL`): trusting a folder "loads that directory's skills, plugins, MCP servers, and hooks". Instructions are not on that list, so a temp copy (often untrusted on macOS/Linux) still gets its `AGENTS.md`.
- **`COPILOT_CUSTOM_INSTRUCTIONS_DIRS`** (spike): an extra folder's `.instructions.md` files are listed, but its `AGENTS.md` only shows as a generic "Nested AGENTS.md" entry. Not reliable enough to inject an ablated `AGENTS.md`: the ablation uses copies instead.
- **`applyTo: "**"`** (spike, `copilot instruction list --json`): the file is listed **without** `applyTo` and without its `description`, like an always-on file. `"**/*.md"`, `"docs/**"` and comma lists (`"README.md,docs/**/*.md"` → `["README.md", "docs/**/*.md"]`) are listed as globs.
- **Skills** (`copilot skill --help`): project skills come from `.github/skills/`, `.agents/skills/` or `.claude/skills/`; `copilot skill list --json` lists one in `.agents/skills/grade-appeal/` with `"source": "project"`.

```js
stats(values) → { n, mean, sd }          // sample standard deviation (n − 1), 2 decimals; n < 2 → sd 0
```

**Interfaces:**

```js
// scripts/check-instructions.mjs
lintAll(root) → Finding[]        // lint(root) from lint-instructions.mjs, as findings with severity
drift(root) → Finding[]          // paths in backticks that don't exist; applyTo globs that match nothing; a canary
                                 // that names another package; a suite case whose canary isn't in that AGENTS.md
coverage(root) → Finding[]       // every package has an AGENTS.md and a suite case; every instruction file an owner
ownersOf(codeowners, file) → string[]   // last matching line wins; a line without owners un-owns
check(root, { strict }) → { code: 0 | 1 | 2, findings }
Finding = { check: 'vague'|'duplicate'|'contradiction'|'command'|'drift'|'coverage'|'owner', severity: 'error'|'warning', file, line, message }
// vague and duplicate are warnings; the rest are errors. Exit 0 clean, 1 errors (or warnings with --strict), 2 the gate failed.

// scripts/canaries.mjs
score(kase, answer) → { id, pass, missing: string[], leaked: string[] }
// evals/canaries.json: { prompt, cases: [{ id, cwd, expect: string[], forbid: string[] }] }
```
