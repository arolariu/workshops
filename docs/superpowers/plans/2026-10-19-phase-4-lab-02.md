# Phase 4 · Lab 02: Skills, five tiers

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lab 02's homework ladder per spec §5.4: grow 🟡 medium "A command you call by name" (30–45 min) and 🔴 hard "A skill with a script" (1–1.5 h), and add 🟣 hard+ "Vet before you trust" (1.5–2 h) and 💎 hard++ "A library that routes" (2–3 h), each in the ticket format with milestones, hints, takeaway, quiz and going further.

**Architecture:** Each tier starts from the reference result of the tier before it (`src/` = predecessor `sol/` + this level's starter files). The skill library grows along the row: `explain-error` (medium) → `release-notes` with a tested script (hard) → a vetter in `scripts/vet-skill.mjs` and one vetted third-party skill installed, `csv-export` (hard+) → six skills with canaries, a routing eval in `evals/routing/` and a skill split with `references/` (hard++). Checks import the learner's modules with `t.import`, run their scripts in temp copies, build throwaway git repositories and skills at check time, and compare with small committed fixtures and goldens.

**Tech Stack:** Node 22+ ESM, `node:child_process`, `node:test`, the check kit (`labs/_harness/kit.mjs`), git (for the `needs: ['git']` checks), no npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-agent-harness-workshop-experience-design.md` §5.4 (Lab 02 row, threads 📏 and 🪙), §5.3, §5.1, §5.2; overview plan `docs/superpowers/plans/2026-10-19-phase-4-ladders.md` (Global Constraints apply to every task here); the exemplar `docs/superpowers/plans/2026-10-19-phase-4-lab-05.md`.

## Global Constraints

See the overview plan. In short: tier times (🟡 30–45 min · 🔴 1–1.5 h · 🟣 1.5–2 h · 💎 2–3 h); the ticket format; free checks decide and are deterministic (`needs: ['git']` / `needs: ['copilot']` for machine-dependent ones); starters fail meaningfully at M1; hard+ and hard++ starters carry a `TODO(Mn)` marker per milestone; `sol/` passes everything including the advisory group; ≤ 2 agent-check prompts per level and ≤ 3 new or changed prompts in the whole lab; easy unchanged; todo code blocks ≤ 74 columns; no npm dependencies; nothing Copilot would load by accident (vendor skills live in `vendor/`, never in a skills folder).

## Skill facts this lab relies on (Copilot CLI 1.0.101-0, free commands and docs, 20 Oct 2026)

- **Where skills load from:** `.github/skills/`, `.agents/skills/`, `.claude/skills/` (project), `~/.copilot/skills/`, `~/.agents/skills/` (personal), plugins, and directories added with `copilot skill add <dir>` (`copilot skill --help`). `vendor/<name>/SKILL.md` is none of these, so the vendor skills of hard+ never load. `--add-dir <dir>` loads `<dir>/.github/skills`, not `<dir>/<name>/SKILL.md`.
- **`copilot skill add --project <file>/SKILL.md` copies only `SKILL.md`** into `.github/skills/<name>/`; a skill's `scripts/` are not copied. Evidence (free, in a temp git folder; `~/.copilot/settings.json` and `config.json` hashes unchanged before and after):
  ```text
  > copilot skill add --project .\src\demo-skill\SKILL.md
  Added project skill "demo-skill" from file.
  Created …\.github\skills\demo-skill
  > Get-ChildItem -Recurse .github  →  .github\skills\demo-skill\SKILL.md   (no scripts\hi.mjs)
  ```
- **`copilot skill add <directory>` registers the directory in your personal settings** ("Register a directory of skills (added to your settings)", `copilot skill add --help`): pointed at `vendor/`, it would load all three vendor skills, the malicious one included, in every project.
- **Frontmatter:** `name`, `description` (required); `license`, `argument-hint` (since 1.0.64), `disable-model-invocation` (since 0.0.412, "fully honored" since 1.0.74), `allowed-tools` (pre-approves tools; the docs warn: only pre-approve `shell`/`bash` for skills you reviewed and fully trust). Source: <https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills> and the CLI changelog <https://github.com/github/copilot-cli/blob/main/changelog.md>.
- **Skill calls in JSON events:** `--output-format json` shows a loaded skill as `{"type":"tool.execution_start","data":{"toolName":"skill","arguments":{"skill":"<name>"}}}` (seen in `labs/.runs/lab-00-easy/20261019-190558-133659/case-1/stdout.txt`, where a **personal** plugin skill, `using-superpowers`, loaded on a lab prompt). Personal and plugin skills compete for the same requests.
- **Embeddings-based skill retrieval:** 1.0.66 added a **persisted** `dynamicRetrieval` setting and `--dynamic-retrieval skills=<on|off>` ("enable or disable embeddings-based retrieval of skills", changelog). With it on, a retriever can pre-select skills before the model sees their descriptions; that is the closest real thing to the lexical pre-check of hard++. The flag **persists the choice in the user's settings**, so the eval never passes it.
- `node --test` (npm test) does **not** scan dot folders: a test file in `.github/skills/<name>/scripts/` only runs when named (`node --test .github/skills/release-notes/scripts/changes.test.mjs`). Verified with a temp folder: only `b.test.js` ran, not `.github/skills/x/scripts/a.test.mjs`.

## Deviations from the spec

| Spec | This plan | Why |
|---|---|---|
| Medium "It must handle three crash fixtures" | The three crashes come from three real bugs in the starter (`print-report.js` can't even start); the learner runs `/explain-error` on each and fixes them. The free checks prove the fixes and the skill's rules for each crash shape (project frame, thrown on purpose → the caller, no project frame → the first line); the agent check runs the skill on one crash. | A free check can't run the model; the outcomes it can check are the fixes and the rules the skill states. |
| Medium "a justified choice about whether the model may call it" | `disable-model-invocation` set explicitly (true or false) with a YAML comment of 6+ words saying why, and the description/body consistent with the choice. The reference says `false` (read-only, people paste traces without remembering the command). | A comment next to the key is where a reviewer looks, and it isn't part of the description that is in every turn's context. Hard++ needs `explain-error` model-invocable to route to it. |
| Medium agent check prompt | `/explain-error fixtures/crash.txt` (the prompt starts with the command, as a person types it) and the expected line moves to `report.js:12`. | The slash form works whichever invocation choice the learner made; `report.js` gains an import, so the crash line moves from 11 to 12. |
| Hard "golden output proves [the skill never invents]" | The script renders the release-notes Markdown itself (`--format md`); a golden file pins that output for a fixture history; the skill pastes it verbatim. | The entries are produced by code, so the model has nothing to invent; the golden proves the code. |
| Hard "has unit tests" | Plus **mutants**: the learner's suite must pass on the reference script (control) and fail on five broken versions built at check time. | "Prove it" (same as Lab 05 hard): a suite that never fails proves nothing. |
| Hard+ "review three third-party skills … write `VERDICT.md`" | Plus: install the one that passes (copy the folder to `.github/skills/csv-export/`), and prove the other two load nowhere. | Vetting ends in a decision; `copilot skill add --project` only copies `SKILL.md` (see facts), so a folder copy is the install. |
| Hard+ "writes outside the repo" | Detected per line (a write call and an outside target on the same line); `VERDICT.md` lists what static vetting can't see. | A static, line-based vetter is honest about its limits; the limits are part of the lesson. |
| Hard++ "Six skills with overlapping jobs" | The six are the four the row already built (`new-module`, `explain-error`, `release-notes`, `csv-export`) plus two starters that overlap them: `write-tests` (vs `new-module`) and `write-docs` (too broad: changelogs, errors, exports…). | The library grows along the row instead of starting over. |
| Hard++ "split a skill that's too broad" | `write-docs` keeps its name: its description is narrowed to its own job, and its body is split into a short `SKILL.md` plus `references/*.md` read on demand; the parts other skills own are removed. | The 24 requests name six skills; renaming or adding skills would change the eval. The split is the progressive-disclosure lesson (🪙). |
| Hard++ "a free lexical pre-check" | Spelled out as an IDF-weighted word overlap between request and description (`route.mjs`); the checks grade the descriptions with their own copy of it, so descriptions are the only lever; plus a budget of 1,500 characters for all six descriptions. | Deterministic and free; a budget keeps descriptions from being stuffed with the eval's words (they are paid on every turn). |
| Hard++ "an opt-in real run" | `node evals/routing/run.mjs --real --max-credits N` runs each request with `copilot -p … --deny-tool=write --deny-tool=shell --max-ai-credits=N` in place (trusted folder), reads the canaries; it refuses without `--max-credits`. The checks test it with an injected fake `ask`, never Copilot. | Skills only load in trusted folders, so a temp copy outside the workshop would not route at all; read-only flags make running in place safe. |

```js

group(commits /* [{ hash, message }] */) → { total, groups: { type: [{ hash, scope, subject }] }, breaking: [{ hash, type, scope, subject, note }], reverted: [{ hash, scope, subject, by }] }

render(data, { version = 'Unreleased', date = null }) → string   // the Markdown section, exact format in todo.md
readGit({ cwd }) → { since, commits }                             // given: last tag, full messages
readFrom(file) → { since: null, commits }                         // given: .json [{ hash, message }] or "<hash>\t<subject>" lines
CLI: changes.mjs [--from FILE] [--format json|md] [--version X] [--date YYYY-MM-DD]
```

### Task 4: Hard++ · A library that routes (new)

**Files (new level `labs/lab-02/hard-plus-plus/`):** `todo.md`, `src/`, `sol/`, `tests/checks.mjs`, `tests/helpers.mjs` (the checks' own pre-check and metrics), `tests/agent.mjs`, `tests/fixtures/{requests.json,routing-results.json,routing-metrics.json}`.

**Starter files (on top of hard+'s `sol/`):**

- `evals/routing/requests.json` (24 requests: 3 per skill, 6 that need no skill), `evals/routing/route.mjs` (given `STOPWORDS`, `MIN_SCORE = 2`, `tokens`, `loadSkills`, `library`; TODO(M2) `score`, `route`), `evals/routing/metrics.mjs` (TODO(M3) `canaries`, `metrics`, `report`), `evals/routing/run.mjs` (given `askCopilot`, file writing; TODO(M4) `realArgs`, `main`).

**Interfaces:**

```js
// route.mjs
tokens(text) → string[]           // given: lower-case words of 3+ letters, minus STOPWORDS, one trailing "s" off
loadSkills(root) → [{ name, description, dir }]   // given: .github/skills/*/SKILL.md
library(skills) → { skills: [{ name, words: Set }], df: Map, size }  // given
score(request, entry, lib) → number   // Σ log(1 + size / df(w)) over the distinct request words the entry has
route(request, lib) → name | null     // best score ≥ MIN_SCORE and no tie for first, else null
// metrics.mjs
canaries(answer) → string[]           // [skill:name] tags, unique, in order
metrics(results /* [{ id, request, expect, got: [] }] */, names) → { perSkill: [{ skill, expected, routed, tp, fp, fn, precision, recall }], macro: { precision, recall }, none: { total, left }, misses: [{ id, request, expect, got }] }
report(m, { mode: 'lexical' | 'real' }) → string   // Markdown, format in todo.md
// run.mjs
realArgs(request, { credits }) → string[]  // -p, -s, --no-ask-user, --max-ai-credits=N, --deny-tool=write, --deny-tool=shell
askCopilot(request, { credits, cwd }) → string   // given
main(argv, { ask, root, log }) → Promise<exit code>  // lexical by default; --real needs --max-credits N (else 2)
```
