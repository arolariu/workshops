## Spike: gh-aw facts this lab relies on (20 Oct 2026, gh-aw v0.92.0, free: `--help`, local `gh aw compile`, docs at tag v0.92.0)

The labs don't pin gh-aw (`SETUP.md`: "run `gh extension install github/gh-aw` yourself"); the version installed here is **v0.92.0**, and every fact below was checked against it. Scratch repos lived in the session folder, never in the workshop tree; nothing touched a real repository or needed a token.

**The compile model (medium).**
- `gh aw compile` writes `<name>.lock.yml` with a first line `# gh-aw-metadata: {"frontmatter_hash":"…","body_hash":"…","compiler_version":"v0.92.0",…}`. The body is **not** compiled in: the lock has `GH_AW_PROMPT_CONTENT_…: "{{#runtime-import .github/workflows/issue-triage.md}}"`, so the agent reads the body at run time.
- `gh aw hash-frontmatter <file>` (free, local) shows what counts. Measured: a body edit → same hash; `${{ github.repository }}` added to the body → same hash; `${{ vars.TRIAGE_TONE }}` added to the body → **new hash**; a YAML comment added inside the frontmatter → **new hash**; two keys swapped → **new hash**. Its help: the hash covers "all frontmatter fields from the main workflow, frontmatter from all imported workflows, template expressions containing env. or vars. from the markdown body, version information".
- At run time the activation job runs `check_workflow_timestamp_api.cjs`, which recomputes the hash and stops a run whose lock is stale (`stale_lock_file_failed`). So a frontmatter change without a recompile breaks the next run; a body change never does.
- `max-ai-credits: 50` compiles to `GH_AW_MAX_AI_CREDITS: "50"`. `max-daily-ai-credits` exists (a 24-hour cap per workflow, checked by the activation job). `schedule: daily` compiles to a scattered cron (`39 3 * * *  # Friendly format: daily (scattered)`).

**Imports and shared configuration (hard, hard++).**
- `imports: [.github/agents/reviewer.agent.md]` compiles in strict mode: the agent file becomes `{{#runtime-import .github/agents/reviewer.agent.md}}` before the workflow body (one agent file per workflow). Its `tools:` line is not used by gh-aw: the workflow's own `tools:` decide.
- A file without `on:` (for example `.github/workflows/shared/fleet.md`) is a **shared component**: validated, importable, never compiled on its own. Docs (imports.md at v0.92.0): an import may carry `tools`, `mcp-servers`, `safe-outputs`, `network`, `permissions` (validated only: the main workflow must declare them), `runtimes`, `env`, steps, `checkout`, `github-app`; other fields "generate warnings and are ignored". Merge rules: `network.allowed` is a union; each safe-output type is defined once (the main wins); tools deep-merge.
- **The compiler disagrees with that docs list** (measured with `gh aw compile weekly-report --strict` and the lock's env, v0.92.0): `max-ai-credits: 77`, `max-daily-ai-credits: 333`, `max-turns: 11` and `concurrency: { group: shared-group }` in the shared file all reached the importer's lock (`GH_AW_MAX_AI_CREDITS: "77"`, `GH_AW_MAX_DAILY_AI_CREDITS: "333"`, `GH_AW_MAX_TURNS: 11`, `group: shared-group`); with the importer setting its own values (150, 200, 40, its own group), the importer's won. Refused in a shared file (compile errors): `timeout-minutes` ("cannot be used in shared workflows (only allowed in main workflows with 'on' trigger)") and `concurrency.cancel-in-progress` ("can only include import-safe fields group and job-discriminator"). So a shared file can hold fleet **defaults**; timeouts and cancel behaviour stay per workflow.
- Compiled in strict mode: a shared file with `network: defaults`, `tools.github.min-integrity: approved`, `safe-outputs: { mentions: false, allowed-domains: [github], report-failure-as-issue: ["!inference_access_error"] }`, imported by a weekly report with `concurrency`, `max-daily-ai-credits`, `max-turns` and `create-issue { title-prefix, max: 1, close-older-issues, expires }`.
- A change to the shared file's frontmatter changes the hash of **every** workflow that imports it (measured: `max-turns: 11 → 12` in the shared file moved `weekly-report`'s hash; a shared **body** edit didn't). The shared body reaches the prompt as `{{#runtime-import .github/workflows/shared/fleet.md}}`, before the workflow's own body.

**Hostile input (hard+).**
- gh-aw refuses raw untrusted text in the prompt: `${{ github.event.comment.body }}` fails to compile ("unauthorized expressions … did you mean: github.event.comment.id?"). The allowed list still includes `github.event.issue.title` and `github.event.pull_request.title`, which strangers write. The sanitized channel is `${{ steps.sanitized.outputs.text }}` (URLs outside `allowed-domains` redacted).
- Strict mode is **not** a security review: this compiles with `--strict`: `issue_comment` trigger, `toolsets: [default]`, `min-integrity: none`, `bash: ["curl:*"]`, `network: { allowed: [defaults, "*"] }`, `add-labels { allowed: [question, needs-maintainer, approved], max: 3 }`, `add-comment { max: 2, target: "*" }`, and the raw issue title in the body. That is the hard+ starter.
- `add-labels.max` counts **calls** (default 5); `max-labels` caps labels **per call** (default 10). `blocked` (globs) is checked before `allowed`. `target` defaults to the triggering item; `"*"` reaches any item.
- Mentions (`sanitize_content_core.cjs` at v0.92.0): by default an `@mention` survives when the user is a collaborator (`allowed-collaborators`, default true) or part of the event context (`allow-context`, default true); `mentions: false` escapes all. Output URLs: default allowed domains are `github.com, github.io, githubusercontent.com, githubassets.com, github.dev, codespaces.new`; others become `(redacted)`.
- Integrity filtering (`tools.github.min-integrity`): `merged > approved > unapproved > none`; `OWNER/MEMBER/COLLABORATOR` are `approved`, `CONTRIBUTOR/FIRST_TIME_CONTRIBUTOR` `unapproved`, `NONE` `none`; default `approved` for public repositories and `none` for private ones; `approval-labels` promote an item to `approved`. So an agent that can add a label listed in `approval-labels` can raise the trust of the text that tricked it.
- `network: { allowed: ["*"] }` compiles (the firewall gets `"*"`), but `safe-outputs.allowed-domains: ["*"]` is rejected ("wildcard-only domain '*' is not allowed").
- The `defaults` ecosystem at v0.92.0 is: `api.snapcraft.io, archive.ubuntu.com, azure.archive.ubuntu.com, crl.*` (geotrust, globalsign, identrust, sectigo, thawte, usertrust, verisign), `crl3/crl4.digicert.com, crls.ssl.com, json-schema.org, json.schemastore.org, keyserver.ubuntu.com, ocsp.*` (digicert, geotrust, globalsign, identrust, sectigo, ssl.com, thawte, usertrust, verisign), `packagecloud.io, packages.cloud.google.com, packages.microsoft.com, ppa.launchpad.net, s.symcb.com, s.symcd.com, security.ubuntu.com, ts-crl.ws.symantec.com, ts-ocsp.ws.symantec.com, www.googleapis.com` (read from a compiled lock's `allowDomains`).

**Running it (hard++).**
- Failure handling: `safe-outputs.report-failure-as-issue` (default true) takes a list of categories, `!` to exclude (`agent_failure`, `timed_out`, `missing_safe_outputs`, `report_incomplete`, `inference_access_error`, `ai_credits_rate_limit_error`, `max_ai_credits_exceeded`, …). `noop` must be called when nothing is needed ("the #1 runtime failure mode"). `max-turns` caps model turns (default 500).
- Concurrency: gh-aw generates per-workflow groups (issues: per issue, no cancel; PRs: per PR, cancel in progress; schedule: per workflow); `concurrency:` in the frontmatter overrides it.
- `gh aw logs --json` output: `gh aw json-schema logs` (free, local) prints its JSON Schema. Required top level: `summary, runs, episodes, edges, logs_location`; `summary` requires `total_runs, total_duration, total_action_minutes, total_turns, total_errors, total_warnings, total_missing_tools, total_missing_data, total_safe_items, total_driver_exit_failures, total_agent_logic_failures, total_episodes, high_confidence_episodes` (plus `total_aic`, `total_tokens`); each run requires `run_id, number, workflow_name, workflow_path, status, classification, token_usage, aic, created_at, url, logs_path, event, branch` (plus `conclusion, failure_kind, duration, action_minutes, turns, error_count, safe_items_count`). `aic` = AI credits. `classification` is `risky|normal|baseline|unclassified`; `failure_kind` is `driver_exit|agent_logic` (from `logs_report.go`).

### Task 3: Hard+ · Hostile input (new)

**Files (new level `labs/lab-07/hard-plus/`):** `todo.md`, `src/`, `sol/`, `tests/checks.mjs`, `tests/common.mjs`, `tests/fixtures/{hostile.json,loose-assistant.md,loose-triage.md}`.

- `fixtures/my-attacks.json`: `{ "_todo": "TODO(M5): …", "cases": [] }`.

**The simulator (`scripts/aw-sim.mjs`):**

```js
parseFrontmatter(text) → { data, body } | null       // its own YAML subset (same rules as the kit)
replay(configs, cases, repo) → Result[]              // configs: { [workflowId]: { data, body } }
simulateCase(config, testCase, repo) → Result
contextFindings(config) → string[]                   // raw attacker-written fields, broad toolsets, low min-integrity
Result = { id, workflow, kind: 'hostile'|'benign', verdict: 'blocked'|'got-through'|'works'|'broken',
           effects: [{ kind: 'label'|'comment'|'issue'|'fetch'|'read', item?, label?, body?, host? }], notes: string[] }
```

Case format (inert JSON: what a tricked agent would *propose*; nothing runs):

```text
{ id, workflow: "issue-assistant"|"issue-triage", kind: "hostile"|"benign", milestone, story,
  trigger: { item: 41, author: "mallory", association: "NONE" } | { scheduled: true },
  proposals: [ { type: "add_labels", labels: [...], item? } | { type: "add_comment", body, item? }
             | { type: "create_issue", title, body } | { type: "fetch", url } | { type: "read", item, association, labels? }
             | { type: "<other handler>" } ],
  goal: { label } | { labels: n } | { mention } | { item } | { host } | { read },          // hostile: it got through if met
```
