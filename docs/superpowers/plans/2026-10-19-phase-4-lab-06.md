## Spike: the marketplace format and the free CLI commands (20 Oct 2026, Copilot CLI **1.0.101-0**, 0 prompts)

The brief named 1.0.99-2; `copilot --version` says 1.0.101-0 (auto-updated). All commands below are free (no prompt). The user's real configuration was never touched: every add/install ran with `COPILOT_HOME=<scratch folder>` (deleted afterwards). Docs read: [About CLI plugins](https://docs.github.com/copilot/concepts/agents/copilot-cli/about-cli-plugins), [Creating a plugin marketplace](https://docs.github.com/copilot/how-tos/copilot-cli/customize-copilot/plugins-marketplace), [CLI plugin reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference), [Creating a plugin](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/plugins-creating), [About CLI extensions](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-cli-extensions), [Creating an extension](https://docs.github.com/en/copilot/tutorials/create-an-extension), the [hooks reference](https://docs.github.com/copilot/reference/hooks-reference), the APM [lockfile spec](https://github.com/microsoft/apm/blob/main/docs/src/content/docs/reference/lockfile-spec.md) and [manifest schema](https://github.com/microsoft/apm/blob/main/docs/src/content/docs/reference/manifest-schema.md).

**The repository format `copilot plugin marketplace add` reads:**
- A marketplace is a folder (or Git repository) with `marketplace.json` in one of `marketplace.json`, `.plugin/marketplace.json`, `.github/plugin/marketplace.json`, `.claude-plugin/marketplace.json` (checked in that order). Required: `name` (kebab-case, ≤ 64), `owner: { name, email? }`, `plugins: [{ name, source, description?, version?, … }]`; optional `metadata: { description, version, pluginRoot }`. `source` is a path relative to the marketplace root (`./plugins/x` and `plugins/x` are the same) or `{ source: "github", repo, ref | sha, path }` / `{ source: "url", … }`.
- `copilot plugin marketplace add <absolute path>` registers a local folder (it needn't be a Git repo) as `{ "source": "directory", "path": … }` in `$COPILOT_HOME/settings.json`; `marketplace list --json` shows `"source": "Local: <path>"`.
- **Quirk:** `copilot plugin marketplace add ./market` fails: `Failed to fetch GitHub marketplace ./market: Command failed: git clone … https://github.com/./market.git` (the relative path is read as `owner/repo`). `.\market` (Windows) and an absolute path work. → Every command in the lab uses an absolute path (`"$PWD/marketplace"`).
- The CLI validates the schema at `add` time, and only that: no `owner` → `Invalid marketplace.json: owner: Required`; `"name": "Bad_Name"` → `plugins.0.name: Plugin name must be kebab-case (letters, numbers, hyphens, and dots)`. A `source` folder that doesn't exist is accepted by `add` and `browse`; `install` fails later (`Plugin source directory not found: …`). A marketplace entry `ghost` whose `plugin.json` says `"name": "ghost-other", "version": "2.0.0"` while the entry says `1.0.0` installs silently, and `plugin list` reports **plugin.json's** version (`2.0.0`).
- `marketplace browse <name> --json` lists `{ name, description, marketplace }` only (no versions).
- `copilot plugin install <plugin>@<marketplace>` from a local (directory) marketplace prints `It is loaded live from <path> … nothing was copied.`; `plugin list --json` rows are `{ name, marketplace, version, enabled, source: "live", installedFrom }`.
- `copilot plugin install <local path>` works but warns: `Direct plugin installs (repos, URLs, local paths) are deprecated. Only plugin@marketplace installs will be supported in a future release.` (the reason hard++ exists). It copies the plugin to `$COPILOT_HOME/installed-plugins/_direct/<folder>/`.
- `COPILOT_HOME` isolates config, installed plugins and personal skills; `COPILOT_CACHE_HOME` also relocates the **package cache** (the CLI extracted ~208 MB into it), so checks set only `COPILOT_HOME` (and `COPILOT_AUTO_UPDATE=false`). A local marketplace leaves the user's cache (`%LOCALAPPDATA%\copilot\marketplaces`) untouched (compared before/after).

**What `--plugin-dir` exercises for free:** `copilot --plugin-dir <dir> plugin list --json` (row `source: "external"`, with `version`) and `copilot --plugin-dir <dir> skill list --json` (rows `{ name, description, source: "plugin", path }`). **`copilot --plugin-dir <dir> mcp list --json` does not list the plugin's MCP servers** (with `.mcp.json`, and with `"mcpServers": ".mcp.json"`); after `copilot plugin install <dir>` into a scratch `COPILOT_HOME` it does: `sb-portal source=plugin plugin=sb-spike args=mcp/sb-portal.mjs cwd=${PLUGIN_ROOT}` (the default `cwd` of a plugin's stdio server is the plugin root). A manifest path that isn't `.mcp.json` works too (`"mcpServers": "mcp/servers.json"`). There is no list command for agents or hooks: those are checked statically and by running the hook script.

**Plugin hooks:** no doc names an environment variable for hook commands. GitHub's own `github/copilot-plugins` marketplace ships `plugins/build-perf-cpp/hooks/hooks.json` with `"powershell": "./scripts/install-vcperf.ps1"` and no `cwd`, where `scripts/` sits at the plugin root: a plugin hook command runs from the **plugin root**. The payload's `cwd` is the session folder, so a plugin hook writes project files (logs) under `input.cwd`, never under `process.cwd()`. Not verified live (that needs a prompt): the hard agent check does it.

**Extensions:** discovered in `.github/extensions/<name>/extension.mjs`, `~/.copilot/extensions/<name>/` and installed plugins (legacy manifest field `extensions`: path(s) to extension directories); `copilot-cli#3023` ("plugin install does not load joinSession() extensions") was closed as fixed in v1.0.88. A tool is `{ name, description, parameters (JSON Schema), handler(args, invocation) → string, skipPermission?, defer? }`; `session.log(message, { level: "info" | "warning" | "error" })`. Extensions need `--experimental`.

**APM 0.33.0 is installed here** (`apm --version`); lab-06 easy marks APM work `{ env: true }` and Copilot work `needs: ['copilot'], env: true`. `apm audit --ci` is APM's own lock check; hard+ builds a small one so the checks stay offline. Lock facts used: `dependencies[].{ repo_url, resolved_ref, resolved_commit (40 hex), version, deployed_files, deployed_file_hashes }`; hashes are SHA-256 hex over UTF-8 text with CRLF → LF (so a Windows checkout isn't drift).

**Agents vs skills from a plugin (review spike, 20 Oct 2026, 0 prompts).** A scratch project held a copy of the hard plugin plus `.github/agents/sb-reviewer.agent.md` and `.claude/agents/sb-reviewer.md` (both `name: sb-reviewer`), `.github/skills/sb-explain-error/SKILL.md` (`name: sb-explain-error`) and `.github/skills/explain/SKILL.md` (`name: sb-new-module`).
- `copilot --plugin-dir <plugin> --agent nope -p x` (fails before any model call) → `No such agent: nope, available: sb-reviewer, studybuddy-harness:sb-reviewer`. A plugin's agents are **namespaced**: a same-named project agent can't hide the plugin's, it sits next to it, and `/agent sb-reviewer` picks the project's copy (a **look-alike**). The two project copies show once.
- With `tutor.agent.md` (`name: sb-tutor`) and `.claude/agents/helper.md` (`name: claude-helper`) instead: `available: sb-tutor, claude-helper, sb-reviewer, studybuddy-harness:sb-reviewer`. An agent goes by the `name:` in its frontmatter (not its file name), and `.claude/agents/*.md` load too.
- `COPILOT_HOME=<scratch> copilot --plugin-dir <plugin> skill list --json` → only `sb-new-module source=project path=\.github\skills\explain` and `sb-explain-error source=project`: both plugin skills are gone. Skills **shadow**: first-found-wins by `name:`, project first, whatever the folder is called.
