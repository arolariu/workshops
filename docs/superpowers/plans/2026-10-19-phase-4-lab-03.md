# Phase 4 · Lab 03: Custom agents, five tiers

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lab 03's homework ladder per spec §5.4: grow 🟡 medium "A specialist with a boundary" (30–45 min) and 🔴 hard "Two agents, one loop" (1–1.5 h), and add 🟣 hard+ "Privilege audit" (1.5–2 h) and 💎 hard++ "An agent team" (2–3 h), each in the ticket format with milestones, hints, takeaway, quiz and going further.

**Architecture:** Each tier starts from the reference result of the tier before it (`src/` = predecessor `sol/` + this level's starter files). The test-writer proves every finding of `REVIEW.md` with a red test (medium); the review loop hands JSON findings from the reviewer to the fixer under stop rules and a credit cap per round (hard); an audit script works out what every agent can really do and checks it against `.github/policies/roles.json` (hard+); a scripted pipeline runs planner → human gate → implementer → tester → reviewer with contracts, budgets and resume (hard++). Every Copilot call in a script goes through an injectable `run(args)` so the free checks replay recorded answers instead of spending credits.

**Tech Stack:** Node 22+ ESM, `node:crypto`, `node:test`, the check kit (`labs/_harness/kit.mjs`). No npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-agent-harness-workshop-experience-design.md` §5.4 (Lab 03 row, threads 🕵️ The reviewer and 🔐 Least privilege), §5.3, §5.1, §5.2, §5.10; overview plan `docs/superpowers/plans/2026-10-19-phase-4-ladders.md`; exemplar `docs/superpowers/plans/2026-10-19-phase-4-lab-05.md`.

## Agent facts this lab relies on (docs, 20 Oct 2026, Copilot CLI 1.0.101-0; no paid spike)

Sources: [Custom agents configuration](https://docs.github.com/en/copilot/reference/custom-agents-configuration), [CLI command reference · Custom agents reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#custom-agents-reference), [Creating custom agents for the CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli), `copilot --help`, `copilot help permissions`, `copilot help limits`.

- **`tools`:** omitted = every tool; `["*"]`, or `*` anywhere in the list (`["view", "*"]`), = every tool; `[]` = none. A comma-separated string works too. **Unrecognised names are ignored silently.**
- **Aliases (case-insensitive):** `execute` = `shell`, `Bash`, `powershell`; `read` = `Read`, `NotebookRead` (CLI tool `view`); `edit` = `Edit`, `MultiEdit`, `Write`, `NotebookEdit`; `search` = `Grep`, `Glob`; `agent` = `custom-agent`, `Task`; `web` = `WebSearch`, `WebFetch`; `todo` = `TodoWrite`.
- **MCP:** `server/tool` enables one tool, `server/*` every tool of that server. An agent may also bring its own servers (`mcp-servers:` in its frontmatter).
- **Delegation:** `disable-model-invocation: true` (or the CLI's `infer: false`) stops the main agent from picking an agent by inference; it can still be started with `--agent` or `/agent`. A custom agent run as a subagent gets a fresh context and doesn't read `AGENTS.md` unless it sets `include-custom-instructions: true`.
- **Where agents load from:** `~/.copilot/agents/` (wins), `.github/agents/` from the working directory up to the git root, `.claude/agents/`, `--add-dir` roots, plugins. **Subfolders load too** (`agents/team/reviewer.agent.md` has the ID `team--reviewer`), and so do plain `.md` files. So nothing that isn't a real agent may live anywhere under `.github/agents/`.
- **No free listing command for agents:** `copilot instruction|skill|mcp|plugin|lsp list` exist, but the reference says custom agents "require a live session" (`/agent`). The checks read the files.
- **Budgets:** `--max-ai-credits` has a **minimum of 30** per session and is a soft cap; subagents share the session's limit. So a review-then-fix round of two `copilot -p` calls costs at least 60 credits of cap.
- **Tool visibility vs approval:** `--available-tools`/`--excluded-tools` decide which tool schemas the model sees; `--allow-tool`/`--deny-tool` only decide approval, and a deny beats every allow.

**Interfaces (produced, also used by hard++'s answer parsing ideas):**

```js
export const MIN_CREDITS = 30;
export const WEIGHT = { high: 3, medium: 2, low: 1 };
parseReview(text) → { ok: true, verdict: 'CLEAN'|'ISSUES', findings: Finding[] } | { ok: false, error: string }
//   Finding { severity: 'high'|'medium'|'low', location: 'file.js:12', problem: string, suggestion?: string }
//   the LAST ```json block (or the last {...} that parses) wins; CLEAN ⇔ no findings
score(findings) → number                          // sum of WEIGHT
reviewerArgs(file, { credits = 30 } = {}) → string[]
fixerArgs(file, findingsPath, { credits = 30 } = {}) → string[]
roundBudget(creditsPerRound) → { reviewer, fixer } // each ≥ 30, sum ≤ creditsPerRound; RangeError below 60
reviewLoop({ file, maxRounds = 3, creditsPerRound = 60, dir = '.agent-logs/review-loop', run, runTests }) → Promise<Report>
//   run(args) → string (or a promise): one Copilot call; runTests() → { pass, fail }
//   Report { file, maxRounds, creditsPerRound, rounds: Round[], stop, reason }
//   Round { round, verdict, findings, score, credits: { reviewer, fixer|null }, findingsFile|null, tests|null }
//   stop: 'clean' | 'no-progress' | 'max-rounds' | 'unreadable' | 'budget' | 'error'
renderReport(report) → string                     // report.md
```

Writes `<dir>/round-<n>.findings.json` (`{ round, file, verdict, findings }`) before each fix, and `<dir>/report.json` + `<dir>/report.md` at every stop.

**Checks:**

- **M3 · The loop and its stop rules:** with a fake Copilot: clean after two fixes (call order reviewer, fixer, reviewer, fixer, reviewer); every call capped by `roundBudget`; the fixer's prompt names a findings file that holds exactly the review's findings; same score twice → `no-progress` (one fix only); `maxRounds: 2` with progress → `max-rounds` (two fixes); a broken answer → `unreadable` (no fix); 50 credits → `budget` (no call); a failing call → `error` (report still written).
- **M4 · The run report:** `report.json` (rounds, caps, tests, stop) and `report.md` (`| Round | Verdict | Findings | Score | Credits | Tests |`, one row per round, `Stopped: <stop>`), equal to `renderReport(report)`; the dry run prints both agents and their caps.
